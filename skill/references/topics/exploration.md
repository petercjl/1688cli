# 探索型搜索方法

## 判断目标

从杂乱的大类结果中识别主图真实呈现的款式方向，并尽量召回每个相关方向的商品链接，形成供价格与商家筛选的完整候选池。用户只说“平底锅”时先搜索这个大类；搜索标题负责召回，不负责分类。

## 节点与返回

1. **宽词召回。** 输入用户原词/核心品类；输出首轮商品和搜索记录。若原词不是平台常用叫法，可根据首轮标题提出同义词，但要记录派生依据。
2. **建立无文字视觉批次。** 完成商品归并后运行 `research visual-batches`。每批只含商品 ID 和主图地址，最多 10 张；不得把标题、SKU、搜索词、价格或商家放进视觉输入。
3. **逐图打标。** 每轮并发检查这一批最多 10 张图，为每张图单独记录产品主体、轮廓、深浅、形状、把手/耳/盖等部件关系、分格/开孔/纹理等可见标签、可见依据、置信度和判断状态。图片是拼图、多款合集、主体过小或无法读取时标待核验/不可用。材质、涂层、钢号和性能不可凭视觉猜测。
4. **完成后聚类。** 所有可用图片打标完成后，按标签与可见结构相似性聚类。每个商品只有一个主要款式类别；其他可见属性作为标签保留。主要类别必须能用共同的视觉签名解释，代表图需来自该类真实成员。
5. **文字后置复核。** 聚类完成后才读取标题和 SKU，为类别补充平台常用叫法、发现图文冲突，并派生新的搜索词。标题不得改变已经有充分图片证据的类别；冲突时保留图片类别并标记待核验。
6. **拓展与停止。** 用已确认的视觉类别选择代表图继续图搜，或用后置提取的平台词补搜。每轮记录返回行数、新增唯一商品、新增相关商品、新商家和重复比例；停止须基于边际收益、时间/查询预算、已尝试路线或服务边界。当前 CLI 无已验证分页，不能把某词返回的前 N 条当作全部商品。

返回主线：产生查询计划与结果分型后回到 `SKILL.md` 第 4/5 步；最终把分型结果交给输出契约的 `explore` 部分。

## 证据边界

- 类别是从本次商品主图样本归纳，不代表 1688 官方类目或整个平台完整供给。
- 主图只证明可见外形；图片未展示的内部结构、材质、涂层、质量和适用性能仍未知。
- 图搜结果相似度高不等于外观、规格和质量相同。
- 文字提到材质、涂层或适用炉具，只能视为商家声明，待页面资料和样品核验。
- 缺少有价值的新方向时交付“当前已探索范围”，不把空缺说成平台没有货。
