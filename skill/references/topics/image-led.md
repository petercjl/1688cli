# 参考图精确找款方法

## 判断目标

用用户参考图确定款式锚点，再通过图搜和关键词扩展尽量召回可比较的货源。每张图的可见事实与用户文字要求共同构成检索意图；图片不能证明隐藏的材质、厚度、尺寸、认证或使用性能。

## 节点与返回

1. **逐图登记。** 为每张用户图分配 `reference_id`，记录它的可访问来源和用户说明。如果多图是不同角度、不同候选款或关系不清，保留这个状态；关系会影响筛选时先问用户。
2. **逐图首搜。** 用各图独立运行 `products image`，保存原始 JSON 和关联的 `reference_id`。不可访问的图标为 `needs_input`，不生成替代图。
3. **视觉对照。** 将候选主图与对应参考图比较，记录可见形态与部件关系上的相符、差异和遮挡。分成“疑似同款”“相似替代”“不符/证据不足”；不要单凭 CLI 相似度定性同款。
4. **反推平台叫法。** 从相关候选的标题与规格中提取有证据的词，继续文字查询，寻找图搜遗漏的商家和变体；也可选不同角度/款式的真实商品图作为新种子。文字查询须保留参考图的关键可见约束。
5. **交叉核验与比选。** 按 `offer_id` 建唯一商品库，保留每个候选被哪些参考图、词或链接召回及不同 SKU/价格观察。逐条标注疑似同款、相似替代、明显不符或待判断；对相关链接再按规格、标价、起订量和商家筛选。同一商品可在多个逐图视图出现；多图按已确认的图组关系展示。

返回主线：形成逐图查询计划后回到 `SKILL.md` 第 4/5 步；最终把对照结论交给输出契约的 `precise` 部分。

## 证据边界

相似款可能由不同 SKU、尺寸或包装构成。对价格的比较必须标明实际返回规格；供应商身份、报价和质量仍需人工确认。若用户需要严格结构同款而图片角度不足，输出“待补图/待核验”，不要强行判为匹配。
